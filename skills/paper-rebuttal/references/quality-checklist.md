# Quality Checklist & Anti-Patterns（质量检查清单与反模式）

> 来源：TobiasLee/Rebuttal-Skill (Quality Checklist + Anti-Patterns) + 合并本 skill 已有检查项

---

## 一、阶段检查清单

### Stage 0: Rebuttal 可行性

- [ ] 分数已标准化到会议/期刊的分数范围
- [ ] 已识别最强正面信号（至少一个审稿人认可的优点）
- [ ] 已识别最强负面信号（最可能致命的关切）
- [ ] 可行性分类有明确理由（不是仅凭直觉）
- [ ] 若为 LOW_EXPECTED_RETURN，已输出完整重新提交计划
- [ ] 假设和缺失信息已明确声明

### Stage 1: 审稿人意图诊断

- [ ] 每条审稿意见已拆分为原子关切点（不是段落级）
- [ ] 每条原子评论标注了 `underlying_concern`（12 类之一，强制）
- [ ] `interpretation_confidence ≠ HIGH` 的关切生成了意图诊断卡
- [ ] 已识别跨审稿人的共享关切（sharedness）
- [ ] 严重性与决策影响分开标注（两者不绑定）
- [ ] 审稿人之间的冲突已单独标出，未强行统一

### Stage 2: 实验计划

- [ ] 实验已按 P0-P3 + DO NOT RUN 分类（不是无排序的愿望清单）
- [ ] 每个 P0 实验明确指定了要解决的关切点 ID
- [ ] 每个实验有最小可行协议和预期时间
- [ ] 实验和仅需澄清的工作已分开
- [ ] 负面结果的后备回应方案已预备
- [ ] 未推荐仅展示努力但不回答深层关切的实验（DO NOT RUN）
- [ ] 时间预算建议实际可行（不是理想化估计）

### Stage 3: 结果整合

- [ ] 每个新结果已验证：协议是否匹配、指标是否恰当、运行次数是否足够
- [ ] 负面/混合结果诚实报告，未隐藏
- [ ] 结果已映射回对应的关切点 ID
- [ ] 关切点状态已更新（resolved / partially_resolved / unresolved）
- [ ] 证据缺口已识别，剩余时间是否值得做更多实验已评估

### Stage 4: 反驳稿草稿

- [ ] 每个主要回应使用 Direct Answer → Evidence → Revision 结构
- [ ] 回应按决策关键性排序（致命→重大→中等→轻微）
- [ ] 共享关切已合并回答（未按审稿人逐个重复）
- [ ] 开头摘要包含感谢 + 认可优点 + 总结关切
- [ ] 每条声明有 provenance 标签
- [ ] 每条承诺在 REVISION_PLAN 中有对应项
- [ ] 字符数已计数，超出限制时按压缩顺序处理
- [ ] pivotal 审稿人回复含 ≥ 2 项防御动作

### Stage 5: 安全门禁

- [ ] Provenance 门：每条事实陈述有 source_provenance
- [ ] Commitment 门：草稿 ↔ REVISION_PLAN 双向一致
- [ ] Coverage 门：无 open 残留 issue
- [ ] 无敌对语气（扫描避免表达清单）
- [ ] 无匿名泄漏
- [ ] 无未确认权限内容
- [ ] 无高风险表述（"显然""全面优于""审稿人误解"等）
- [ ] Thread-local context（per_reviewer_thread 模式）

## 二、诚信检查

- [ ] 无捏造的实验值或数字
- [ ] 无编造的审稿人引语或原稿位置
- [ ] 计划中的工作未表述为已完成（"will add" ≠ "we added"）
- [ ] 未暗示审稿人同意（如果未明确同意）
- [ ] 未声称统计显著性但缺少所需检验
- [ ] 负面新增结果未隐藏
- [ ] 模糊的审稿人意图未表述为确定的
- [ ] 未承诺未来实验一定会成功
- [ ] 未推荐没有可解释对照的仓促实验
- [ ] 不确定时已说明情况并提供最安全的下一步行动

## 三、反模式（Anti-Patterns）— 绝对不要做的事

### 诊断阶段

| ❌ 反模式 | ✅ 正确做法 |
| :--- | :--- |
| 在识别真正问题前就草拟精美 rebuttal | 先完成 Stage 0 决策门 + Stage 1 深层诊断 |
| 将每条审稿意见视为同等重要 | 按严重性 + 决策影响 + 共享性排序 |
| 假设模糊的审稿人意图而不确认 | 生成意图诊断卡，要求作者澄清 |
| 把审稿人的表述不佳归因于审稿人能力不足 | 改写为"我们的表述可能导致了混淆" |

### 实验阶段

| ❌ 反模式 | ✅ 正确做法 |
| :--- | :--- |
| 推荐无排序的实验清单 | P0-P3 + DO NOT RUN 五级分类 |
| 优先做容易的 P2 工作而非关键的 P0 | P0 必须优先，即使更困难 |
| 运行不能回答深层关切的实验 | 每个实验必须映射到具体关切点 ID |
| 用未来的承诺代替当前证据 | "will add in camera-ready" 不如现在展示已有证据 |
| 在所有审稿都远低于录取线时仍耗尽反驳期 | 建议转向重新提交（Stage 0 决策门） |
| 仅因实验容易就跑，不顾是否改变决定 | 问"这个实验能改变决定吗？"再决定是否跑 |

### 撰写阶段

| ❌ 反模式 | ✅ 正确做法 |
| :--- | :--- |
| 将直接答案埋没在背景中 | 第一句就给出直接答案 |
| 攻击审稿人能力或动机 | 保持专业、冷静、精确 |
| 重复感谢占用字符预算 | 开篇一句感谢即可 |
| 跨审稿人重复回答相同关切 | 合并共享关切，一次回答 |
| 删除决策关键证据来压缩字数 | 按压缩顺序：冗余→致谢→措辞→次要→但保留关键回答 |

### 多轮讨论

| ❌ 反模式 | ✅ 正确做法 |
| :--- | :--- |
| 审稿人正确时继续争论 | 让步，1 句确认 + 转 limitations |
| 用修辞升级代替技术升级 | 补实验/补引用优于"再解释一遍" |
| 对无理要求长篇回应 | 礼貌 1 句确认 + 不再纠缠 |

## 四、压缩规则（字数超限时）

按以下优先级删除，**绝不删除关键回答**：

| 顺序 | 删除内容 | 保留内容 |
| :--- | :--- | :--- |
| 1 | 重复感谢 | — |
| 2 | 重复的审稿人引文 | — |
| 3 | 一般背景介绍 | — |
| 4 | 形容词和修辞性语言 | — |
| 5 | 跨审稿人的重复回应 | — |
| 6 | 低影响的次要评论（severity=minor） | — |
| 7 | 解释证据非必需的实现细节 | — |
| — | — | 直接答案 |
| — | — | 关键数字和比较 |
| — | — | 不确定性、假设 |
| — | — | 声明缩小 |
| — | — | 稿件修改 |
| — | — | 未解决的限制 |

## 五、回应模式速查（Direct Answer → Evidence → Revision）

每个主要回应遵循三步骤结构：

```
C1. 描述性标题 — [reviewer IDs]
──────────────────────────────────────────
关切：[忠实的一句话转述审稿人的深层关切]
回应：[第一句直接回答 — 同意/不同意/部分同意 + 核心论证]
证据：[结果、推导、原稿位置、表格编号]
修订：[论文中的确切更改 — "We will add X to Section Y"]
──────────────────────────────────────────
```

示例：
```
C1. Fairness of Baseline Comparison — R1, R3
──────────────────────────────────────────
关切：Is the gain over Baseline-X due to unfair hyperparameter tuning?
回应：We agree that fair comparison is critical. We re-ran all baselines
      under matched tuning budgets (Table R1).
证据：Table R1: 3 datasets × 5 baselines × matched HP budget.
      Our method still achieves +8.2% avg gain (p < 0.01, paired t-test).
修订：We will add the matched-tuning protocol to Appendix C and
      clarify this in Section 5.2.
──────────────────────────────────────────
```
