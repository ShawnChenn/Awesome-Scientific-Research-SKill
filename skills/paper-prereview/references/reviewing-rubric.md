# Reviewing Rubric — 审稿客观标尺

蒸馏自 NeurIPS / ICLR / ACL 官方审稿指南。两种模式的判据都在这。

## 第一节：四大评审维度

| 维度 | 含义 | 关注点 |
| :--- | :--- | :--- |
| **Soundness** | 方法是否严谨正确 | 假设合理性、实验设计、统计显著性、baseline 充分性 |
| **Clarity** | 表达是否清晰 | 逻辑连贯、图表自解释、术语定义、可复现性描述 |
| **Significance** | 贡献是否重要 | 对领域的推动、应用场景、启发后续工作 |
| **Originality** | 是否新颖 | 相对近期 SOTA 的增量、与已有工作的区分 |

## 第二节：各会议评分量表（节选）

| 会议 | 评分项 |
| :--- | :--- |
| **NeurIPS** | Soundness (1–4)、Presentation (1–4)、Contribution (1–4)、Overall (1–10)、Confidence (1–5) |
| **ICLR** | Confidence (1–5)、Soundness (1–4)、Presentation (1–4)、Contribution (1–4)、Rating (1–10)、Reviewfit |
| **ACL / ARR** | Summary、Strengths、Weaknesses、Questions、Rating (1–5 或 1–10)、Confidence |

> 没指定 venue 时默认按 NeurIPS 通用量表，并提示"换 venue 量表会变"。

## 第三节：Reviewer 2 必查清单（Soundness 重点）

- [ ] baseline 是否充分、是否为同期 SOTA（非只比旧方法）
- [ ] 是否缺少关键 ablation（组件贡献不明）
- [ ] 是否有混淆变量（数据泄漏 / 未控变量）
- [ ] 统计显著性是否检验（方差 / 多次种子）
- [ ] 实验设置是否与声称匹配（数据集规模、split 方式）
- [ ] 过拟合承诺（声称泛化但只在单一分布验证）
- [ ] 计算/资源声明是否诚实

## 第四节：好评审 vs 烂评审标准

**好评审：**
- 每条弱点钉到具体位置
- 区分实质问题 vs 误读风险 vs 打磨建议
- 语气专业、中性、善意
- 建议可执行（"补 X 实验验证 Y"而非"需要更多实验"）

**烂评审：**
- 泛泛而谈（"不够清晰""贡献有限"无出处）
- 脑补缺陷、为凑数硬挑
- 情绪化、挖苦、人身攻击
- 发出不正当批评（见 H1–H17）

## 第五节：H1–H17 公正性防火墙（ illegitimate critiques 黑名单）

> 任何 weakness 提出前，先对照此表。命中即**删除或降级为温和建议**，绝不当硬伤。

| 编号 | 不正当批评类型 | 示例 |
| :--- | :--- | :--- |
| H1 | 以"不够新颖"为由拒稿但不给具体对比引用 | "没什么新意" 但无参照文献 |
| H2 | 要求必须超过所有 SOTA 才算贡献 | "没超过 SOTA 所以 reject" |
| H3 | 仅因方法简单而贬低 | "方法太简单，不值得发表" |
| H4 | 要求作者做超出范围的大量额外实验 | "你应该再跑 10 个数据集" |
| H5 | 把局限性等同于缺陷 | "有局限=有缺陷" |
| H6 | 以作者未知文献为由贬低（实则相关但非必须） | "没引 X 所以 reject" |
| H7 | 基于错误理解原文的批评 | 曲解公式/实验设置 |
| H8 | 与已有评审重复的冗余点 | 同一点重复算多条例 |
| H9 | 以写作风格/语言非母语为由拒稿 | "英语不好所以 reject" |
| H10 | 要求引用审稿人自己工作 | "应该引用我的论文" |
| H11 | 以"实验不够多"泛泛要求无具体指向 | 无具体缺哪个实验 |
| H12 | 以负面语气盖过实质 | 情绪化措辞替代论据 |
| H13 | 假设作者未声明的前提 | "你肯定没考虑 X" |
| H14 | 要求不可复现的对比 | 要求对比未开源模型 |
| H15 | 以会议接受率为由压分 | "接收率太低所以 reject" |
| H16 | 双重标准（对自己宽容对作者严苛） | 同问题对自己稿忽略 |
| H17 | 超出论文范围的要求 | 要求论文解决无关问题 |
